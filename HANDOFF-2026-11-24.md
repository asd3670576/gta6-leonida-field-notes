## 9. Known traps on this class of machine (all hit today)

* cargo on GNU needs MinGW `Library\bin` + `Library\x86_64-w64-mingw32\bin` on PATH (dlltool).
* PowerShell 5.1 reads UTF-8 scripts **without BOM** as ANSI → any non-ASCII character (even `…`)
  breaks parsing. Our scripts are ASCII-only now; `port/*.ps1` strip them.
* `git diff > file` from PowerShell writes **UTF-16LE** → `git apply` says "No valid patches in
  input". Use `cmd /c "git diff > file"` or write bytes explicitly.
* Batch files with LF endings mis-parse (`rem` lines executed as commands). Use `.ps1`.
* `Select-Object -First N` on a native command's output can truncate the pipeline and yield
  exit 1 with no output; redirect to a file instead.
* `Invoke-RestMethod` + `ConvertTo-Json -Depth 4` on a hashtable holding a long string produced
  441 KB from 6 KB → HTTP 422. Build the JSON as `'{"body":' + (ConvertTo-Json $s) + '}'`.
* git HTTPS here fails with `SSL_ERROR_SYSCALL`; the REST API works. `port/push_api.ps1` pushes
  our repo through the Data API (tree entries need `mode:"100644"`).
* conda-forge `sdl3` collides with SDL3's own CMake ALIAS targets (`SDL3::SDL3`); use
  `-DCMAKE_DISABLE_FIND_PACKAGE_SDL3=ON` + `FETCHCONTENT_SOURCE_DIR_SDL3`.

## 10. Machine B — 9800X3D (8C/16T) / 32 GB RAM / RTX 5060 **8 GB** / **Windows 11**

### 10.1 What B fixes for free (and why B is the reference machine)

* Win11 ships `ID3D12SDKConfiguration1`, so the **Agility SDK loads** there — the exact thing that
  is closed on A (§2, §6). With Agility loaded, the device reports **Shader Model 6.6**, so
  `runner.rs:101-106` and `preflight.rs:67-69` pass with **no patch**.
* Therefore the whole Win10 change list in §7 is **bypassed on B**, and `XCL_ALLOW_SM65` should be
  left **unset** there — B should behave like upstream. Keep the Win10 work only for A.
* B is the first machine where `d3d12.translated_pipelines` can leave **0** (it was 0 in all three
  A runs, because the recompiler never started) and where the **84 GPU-skipped tests actually run**
  (§6). Use B to learn what "rendering" looks like, then bring that signature back to A.

### 10.2 What B makes worse — the real blockers, ranked

1. **8 GB VRAM vs XCL's console pool.** On A (20 GB) the `advanced` title budget is `uma_mb 4095`;
   XCL maps **3 sparse VRAM windows (12 GiB VA)** plus a coherent window (floor 512 MiB, cap
   4095 MiB), and every sparse page costs host RAM **and** a 64 KiB VRAM tile taken from 64 MiB
   DEFAULT pools (findings 0012). Measured on A: **VRAM 3.0-3.2 GB steady** with the coherent
   window preseeded to 4095 MB — that is ~40 % of B's card before the title's own textures land.
   Expect `E_OUTOFMEMORY` / device removal, the class of failure upstream #345 reports.
   * First run: `-CoherentMb 512` (verified on A) and `-UmaMb 2048`. **Do not** preseed 4095 on B.
   * `cache/uma_coherent.txt` **overrides `uma_mb`** (`uma.rs:170,739`); `XCL_COHERENT_MB` is the
     only real pin (`uma.rs:679-681`). If a run learned a big value, delete the file or pin it.
   * Keep **`XCL_VRAM_ARENAS` unset** (`=1` disables tiling; upstream reports 15 GB of arenas,
     ~2 s stalls and device removal — fatal at 8 GB).
   * `title_memory_mb` shrinks **both** sides (the engine sizes its streaming pools from the
     budget XCL reports). Try 6144/8192 if the title's own `TileHeap … total (6236Mb)` climbs.
2. **32 GB RAM + default page file.** A peaked at private 8.4 GB / commit 45 of 156 GB, so memory
   was never A's limiter. Upstream #505 shows a run growing to **138.9 GB commit**, and #846/#534
   runs still die around **~40 GB private bytes**. On B the commit limit with a system-managed page
   file is ~40 GB, so the wall arrives as what looks like a crash.
   * Set a **fixed** page file before the first long run: initial **32 768 MB**, max **65 536 MB**.
   * This also raises our DXC thread cap: our `dxc.rs` bound is `min(cores-1, GB of free commit at
     startup)`, and it reads commit free, not RAM free.
3. **8C/16T.** `xcl shaders --recomp` (HLSL translation of all 26 698 programs) took **23 s** on
   A's 32 threads; DXIL compilation of the pipelines that actually get used is the long tail, and
   that is what `XCL_DXC_THREADS` bounds. Use **`XCL_DXC_THREADS=8`** for the first runs — upstream
   #505's watchdog was precisely unbounded waits for compute pipeline builds.
4. Disk: `XCL_DUMP_HLSL` writes **9.2 GB**; the package is 208.6 GB. Plan the drive.
5. Close STRATA and anything else holding VRAM before measuring — on A a background STRATA session
   alone accounted for a "full" GPU and produced false OOM readings.
